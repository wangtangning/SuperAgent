SuperAgent 是一个仓库值守 agent

              
你在 GitHub 议题里 @ 它派活，它按策略判断后开工单：独立目录里改代码、跑验证、开 PR，再回到原议题向你汇报。指挥台是它的桌面入口；「进化」页让它从每次工单结果里自动学习。

            


            

              
第 1 步 · 准备两个账号一次性

              

                
你的主账号：派活的人（仓库 owner）。agent 专用账号：免费注册一个（如 xxx-agent），值守以它干活。

                
为什么不能共用？bundle 会忽略 agent 自己发的议题/评论（防自我循环），且 bot 消息不算派活。一个 agent 账号可以服务任意多个仓库——多项目不需要多账号。

              

            


            

              
第 2 步 · 接入向导

              

                
① gh 命令行（自动找/装）→ ② 登录 agent 账号 → ③ 选仓库 → ④ 填授权人（你的主账号）并发单人登录 → ⑤ 加协作者：一键发 Write 邀请，agent 接受 → ⑥ 保存并自检。

                
协作者必须是 Write：agent 要推分支、开 PR。邀请发出后记得用 agent 账号在 GitHub 通知里接受。

              

            


            

              
第 3 步 · 派第一单

              

                
会话页「＋ 新任务」：以你的主账号开议题并自动 @ agent。写明确、范围小的请求，例如「把 README 第 3 行的 xx 改成 yy」。默认策略放行文案/局部样式类小改；大功能会被拒绝或只观察——这是安全边界，不是故障。

                
值守每 60 秒轮询一次。之前开的旧议题没被接收？点会话页「接收已有议题」重置读取基线。

              

            


            

              
第 4 步 · 看它干活

              

                
工单页看阶段/执行器/产出，可重试、停止；会话页看它回议题的汇报；它开的 PR 在仓库里等你评审合并。合并或失败都会成为「进化」页的经验。

              

            


            

              
第 5 步 · 让它进化

              

                
工单结束后自动积累经验；失败聚类/高重试率会变成提示词教训、新技能或并发提案，经校验应用、用后续成功率裁决——改善保留、退化自动回滚。不放心可关「自动应用」，逐张批准。

              

            


            

              
多项目并行一个 agent 账号够

              

                
每个实例盯一个仓库。同机再开一个实例：set SUPERAGENT_PORT=3083 + set SUPERAGENT_HOME=…\.dsh-b 后启动 exe，登录同一个 agent、选另一个仓库即可。同一仓库别跑两个实例。

              

            


            

              
局域网服务器（运维场景）

              

                
「服务器」页存 IP/端口/用户名/密码（DPAPI 加密），分配给 agent 后它用 lan run <id> "命令" 自己登录干活，不再问你密码；密码只在本机助手认证时用，模型上下文只有清单。保存并自检后 Policy 自动加「LAN 运维」授权规则。

              

            


            

              
SSH 密钥（可选）

              

                
agent 要碰私有 git 主机或部署服务器时：在「密钥」页生成/导入私钥（DPAPI 加密存储），点「分配给 agent」，执行器的 git/ssh 自动带上它；公钥复制去 GitHub/服务器登记。连接测试可验证。

              

            


            

              
常见问题

              

                
派活了没反应？ 检查：授权人里有派活账号吗？协作者接受邀请了吗？接入页第 6 步自检绿了吗？旧议题点「接收已有议题」。

                
它拒绝了我的请求？ 默认策略只放行小改；把请求写具体、或按仓库需要在引擎页调整 Policy 规则。

                
数据在哪？ 配置/登录/进化数据：%APPDATA%\superagent-win\；引擎状态：%USERPROFILE%\.dsh\。

SSH 密钥库DPAPI 加密 · 仅本机

            

              
存 agent 要用的 SSH 私钥（私有 git 主机、部署服务器）。分配给 agent 后，执行器的 git/ssh 自动带上这把密钥；不碰你自己的 ~/.ssh。公钥可以贴到 GitHub / GitLab / 服务器的 authorized_keys。

              
「登记到 agent GitHub」需要 agent 登录时授权管理公钥；若提示无权限，用「复制公钥」到 agent 账号 Settings → SSH and GPG keys 手动添加，效果相同。
